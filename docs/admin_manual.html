필수 환경변수

변수명설명설정 방법

이메일 발송 환경변수 v1.3 변경

v1.3.0부터 SendGrid 대신 SMTP(Gmail)를 사용합니다. Gmail 앱 비밀번호를 발급하여 설정합니다.

변수명설명예시값
MAIL_SERVERSMTP 서버 주소smtp.gmail.com
MAIL_PORTSMTP 포트587
MAIL_USE_TLSTLS 사용 여부true
MAIL_USERNAMEGmail 계정yourname@gmail.com
MAIL_PASSWORDGmail 앱 비밀번호 (16자리)xxxx xxxx xxxx xxxx
MAIL_DEFAULT_SENDER발신자 이메일yourname@gmail.com
Gmail 앱 비밀번호 발급 방법:
1. Google 계정 → 보안 → 2단계 인증 활성화
2. 보안 → 앱 비밀번호 → 앱 선택: 메일, 기기: 기타 → 생성
3. 생성된 16자리 비밀번호를 MAIL_PASSWORD에 입력
SECRET_KEY는 반드시 안전한 랜덤 문자열로 설정하세요. 기본값(dev-secret-key) 사용 시 세션 위조 공격에 취약합니다.
환경변수 저장 후 Railway가 자동으로 재배포합니다. 재배포 중 약 1~2분간 서비스가 일시 중단될 수 있습니다.
02-B

관리자 대시보드 뷰 v1.4 신규

관리자 계정으로 로그인하면 대시보드에 전체 사용자의 프로젝트가 사용자별로 그룹화되어 표시됩니다. 일반 사용자의 "내 프로젝트 / 공개 프로젝트" 뷰와 다릅니다.

화면 구성

구성 요소설명
전체 프로젝트 수상단에 시스템 전체 프로젝트 수 표시
사용자 그룹 헤더사용자 아바타, 이름, 아이디, 소속, 직책, 해당 사용자 프로젝트 수
프로젝트 카드해당 사용자 소유의 프로젝트 (사업담당·수행담당 포함)

그룹 정렬 기준

사용자 이름 오름차순으로 그룹이 정렬되며, 각 그룹 내 프로젝트는 최종 수정일 내림차순(최근 것 먼저)으로 표시됩니다.

관리자는 모든 프로젝트를 열람할 수 있지만, 편집·삭제는 해당 프로젝트 소유자만 가능합니다.
사이드바에서도 내 프로젝트 목록이 조직별로 표시됩니다. 관리자 대시보드 뷰는 메인 콘텐츠 영역에서만 제공됩니다.
03

회원 관리

관리자 메뉴(/admin/)에서 모든 회원을 관리합니다. admin 역할을 가진 계정만 접근 가능합니다.

관리자 메뉴 탭 구성 v1.4 개편

탭설명
회원 승인·계정 관리신규 승인 대기 + 전체 회원 목록 통합 (v1.4 개편)
질의응답 현황전체 Q&A 통계 및 최근 질문 목록
질문 유형 AI 분석AI로 질문 유형 분석 후 DB 저장·PDF 내보내기
v1.4에서 전체 회원 탭이 삭제되고 회원 승인·계정 관리 탭으로 통합되었습니다.

회원 상태

상태설명로그인 가능
pending 대기가입 후 관리자 승인을 기다리는 상태불가
active 활성정상적으로 서비스를 이용할 수 있는 상태가능
inactive 비활성관리자가 계정을 정지한 상태불가

회원 역할

역할설명관리자 메뉴
admin 관리자회원 관리, 상태 변경 등 전체 관리 권한접근 가능
member 일반회원프로젝트 생성 및 AI 분석 등 일반 기능접근 불가

신규 회원 승인

1
관리자 메뉴 접속사이드바의 '⚙️ 관리자' 메뉴를 클릭합니다.
2
승인 대기 목록 확인상단 통계에서 '대기' 숫자를 확인합니다. 승인 대기 목록에서 회원 정보(아이디, 이름, 이메일, 조직, 직책, 가입일)를 검토합니다.
3
승인 또는 거절 처리승인 클릭: 상태가 active로 변경되어 즉시 로그인 가능합니다.
거절 클릭: 상태가 inactive로 변경됩니다.
신규 가입 알림 기능은 현재 미구현 상태입니다. 정기적으로 관리자 페이지를 확인하여 승인 대기 회원을 처리해주세요.

회원 상태·역할 변경

작업방법제한사항
상태 변경전체 회원 목록 → 상태 버튼 클릭자기 자신의 상태 변경 불가
역할 변경전체 회원 목록 → 역할 토글 버튼자기 자신의 역할 변경 불가

회원 정보 수정 및 삭제

작업방법수정 가능 항목
정보 수정회원 목록 → 수정 버튼이름, 이메일, 조직, 직책, 비밀번호, 역할, 상태
회원 삭제회원 상세 → 삭제 버튼복구 불가
회원 삭제 시 해당 회원의 모든 프로젝트와 분석 데이터가 함께 영구 삭제됩니다. 삭제 전 반드시 확인하세요.
03-B

질문 유형 AI 분석 v1.4 신규

전체 질의응답 데이터를 AI(Claude Opus)로 분석하여 질문 유형을 분류하고, 서비스 개선 인사이트를 도출합니다. 분석 결과는 DB에 저장되며 PDF로 내보낼 수 있습니다.

AI 분석 실행

1
관리자 메뉴 접속사이드바 '⚙️ 관리자' 클릭 → 질문 유형 AI 분석 탭을 클릭합니다.
2
AI 분석 실행 클릭탭 상단의 '🤖 AI 분석 실행' 버튼을 클릭합니다. 최근 150건의 Q&A를 자동으로 수집하여 분석합니다.
3
분석 진행 대기Claude Opus AI가 질문들을 분석합니다. 데이터 양에 따라 30초~2분이 소요됩니다.
4
결과 확인분석 완료 후 전체 요약, 카테고리별 분류, 주요 이슈, 개선 권고사항이 화면에 표시됩니다.

분석 결과 내용

항목설명
전체 요약분석 대상 Q&A 전체 동향을 2~3문장으로 요약
카테고리 분류질문 유형별 건수, 패턴 설명, 대표 예시, 개선 제안
주요 이슈사용자들이 가장 많이 겪는 어려움이나 니즈 (최대 5개)
기능 개선 권고서비스 개선을 위한 구체적 권고사항 (최대 5개)

결과 저장 및 불러오기

AI 분석 결과는 실행 즉시 DB에 자동 저장됩니다. 다음 접속 시에도 마지막 분석 결과를 바로 확인할 수 있습니다.

분석을 다시 실행하면 새 결과가 DB에 추가로 저장됩니다. 화면에는 항상 가장 최근 분석 결과가 표시됩니다.

PDF 내보내기

1
분석 결과 확인AI 분석이 완료되거나 저장된 결과가 화면에 표시된 상태여야 합니다.
2
📄 파일 저장 클릭탭 우측 상단의 '📄 파일 저장' 버튼을 클릭합니다.
3
PDF 다운로드브라우저가 PDF 파일을 자동으로 다운로드합니다. 파일명: QnA분석결과_YYYYMMDD_HHmm.pdf

PDF 내용 구성

섹션내용
표지분석 제목, 분석 대상 건수, 분석 일시
전체 요약Q&A 동향 종합 요약
카테고리 분류표유형·건수·패턴 설명·개선 제안 4열 표
주요 이슈 & 개선 권고2열 레이아웃으로 이슈와 권고사항 나란히 표시
분석은 필요할 때마다 재실행할 수 있습니다. 신규 Q&A가 많이 쌓인 후 정기적으로 실행하면 서비스 개선 방향 파악에 효과적입니다.
04

데이터베이스 관리

DB 접속 방법

Railway 대시보드 → PostgreSQL 서비스 → Query 탭에서 직접 SQL을 실행할 수 있습니다.

주요 테이블 구조

테이블설명주요 컬럼
users사용자 계정 정보id, username, email, role(admin/member), status(pending/active/inactive), password_hash, reset_token, reset_token_expiry
projects프로젝트 기본 정보id, name, description, organization, business_manager, project_manager, owner_id, is_public
analyses모듈별 입력/분석 데이터id, project_id, module_type, input_data(JSON 문자열), ai_result(HTML 문자열)
qn_a질의응답 게시글id, owner_id, project_id, title, content, ai_answer, ai_pending
qn_a_comment질의응답 댓글id, qna_id, owner_id, content, ai_answer
qna_analysis_results질문 유형 AI 분석 결과 저장 (v1.4 신규)id, result_json(JSON 문자열), analyzed_count, created_at

analyses.module_type 값

6단계 모듈: biz_definition, env_analysis, value_design, revenue_model, execution, validation

환경분석의 AI 결과(ai_result)는 JSON 딕셔너리 형식으로 저장됩니다: {"pestel":"...", "five_forces":"...", "swot":"...", "vrio":"...", "segment":"..."}

스키마 변경 (컬럼 추가)

이 프로젝트는 Flask-Migrate를 사용하지 않습니다. 모델에 컬럼을 추가한 경우 Railway PostgreSQL Query 탭에서 직접 실행합니다.

예: users 테이블에 phone 컬럼 추가
ALTER TABLE users ADD COLUMN phone VARCHAR(20);

DB 백업

Railway PostgreSQL 서비스 → Backups 탭에서 수동 백업을 생성합니다. 대규모 변경 작업 전에는 반드시 백업을 먼저 생성하세요.

전체 데이터 초기화 (위험)

아래 SQL은 모든 데이터를 영구 삭제합니다. 백업 후 신중하게 실행하세요.
전체 초기화 (외래키 의존 순서 준수):
TRUNCATE TABLE qn_a_comment, qn_a, analyses, projects, users RESTART IDENTITY CASCADE;
05

배포 및 업데이트

자동 배포 흐름

1
로컬에서 코드 수정소스 코드를 수정하고 로컬에서 테스트합니다.
2
git commit 및 pushgit add . → git commit -m "메시지" → git push origin main
3
Railway 자동 빌드push 감지 후 Railway가 Docker 이미지를 빌드합니다. 약 1~3분 소요됩니다.
4
배포 완료 확인Railway 대시보드 → Deployments 탭에서 배포 상태를 확인합니다. 서비스에 접속하여 정상 동작을 최종 확인합니다.

로컬 개발 환경 실행

최초 설정:
1. 저장소 클론: git clone https://github.com/heoks99/BizModelCanvas.git
2. 가상환경 생성: python -m venv venv
3. 가상환경 활성화: venv\Scripts\activate (Windows)
4. 패키지 설치: pip install -r requirements.txt (psycopg2 제외 가능)
5. .env 파일 설정 (.env.example 참고)
6. 서버 실행: python run.py → http://localhost:5000

롤백

Railway 대시보드 → Deployments 탭 → 이전 배포 항목 → Rollback 버튼을 클릭합니다.

롤백 시 코드는 이전 버전으로 돌아가지만 데이터베이스 스키마는 롤백되지 않습니다. DB 마이그레이션이 포함된 배포를 롤백할 때는 별도 처리가 필요합니다.

git 태그로 특정 버전 배포

특정 버전 태그로 체크아웃 후 배포:
git checkout v1.3.0
git push origin HEAD:main --force
위 명령은 main 브랜치를 덮어씁니다. 신중하게 사용하세요.

Railway 로그 확인 방법

1
Railway 대시보드 접속https://railway.com/dashboard → BizModelCanvas 프로젝트 클릭
2
웹앱 서비스 선택서비스 목록에서 웹앱 서비스를 클릭합니다.
3
Observability → Logs실시간 로그를 확인합니다. 빨간색 줄이 에러입니다. 에러 발생 시 전체 스택트레이스가 기록됩니다.

비용 모니터링

Railway 대시보드 → Usage 탭에서 이번 달 사용량과 예상 비용을 확인합니다.

웹앱 + PostgreSQL 합산 비용은 월 $1~3 수준입니다. Hobby Plan 포함 크레딧 초과 시 추가 요금이 청구됩니다.

키관리 위치갱신 방법
ANTHROPIC_API_KEYRailway Variablesconsole.anthropic.com → API Keys 재발급 후 Variables 업데이트
MAIL_PASSWORD (Gmail 앱 비밀번호)Railway VariablesGoogle 계정 → 보안 → 앱 비밀번호 재발급
SECRET_KEYRailway Variables변경 시 모든 사용자 세션 초기화됨

접근 제어 구조

  • 모든 페이지는 로그인 필수 (@login_required)
  • 관리자 페이지는 admin 역할 필수 (@admin_required)
  • 프로젝트 편집·삭제는 소유자만 가능
  • 공개 프로젝트는 로그인한 모든 사용자가 읽기 가능
  • 진단 엔드포인트 /api/smtp-check는 로그인 없이 접근 가능 (운영 안정화 후 인증 추가 권장)

장애 발생 시 빠른 대응 순서

1
Railway 로그 확인Observability → Logs에서 에러 메시지와 스택트레이스 확인
2
진단 엔드포인트 확인/api/smtp-check로 환경변수, DB 연결, 외부 서비스 상태 점검
3
환경변수 확인Variables 탭에서 필수 환경변수 누락 여부 확인
4
재배포 시도Deployments → 최신 배포 항목 → Redeploy 클릭
5
이전 버전으로 롤백문제가 최근 배포로 인한 경우, Deployments에서 직전 배포 → Rollback 클릭
